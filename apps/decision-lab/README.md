# Entity Resolution Decision Lab

A static, local-first decision workbench over the frozen evidence snapshot of the
MusicBrainz release-group ↔ Discogs master matching benchmark (test fold, one decision per A
record). It answers one question: *which records should this matching policy accept
automatically, send to review, or leave unresolved, and what evidence and trade-offs justify
that decision?*

Not a production service: no backend, no accounts, no analytics, no network requests other than
the app's own data files under its base path, no external scripts. Every figure is read from the
exported data files; no number from the artifacts is typed into the source.

## Scripts

| script | what it does |
|---|---|
| `npm run dev` | sync the data, then Vite dev server (base path `/entity-resolution/lab/`) |
| `npm run build` | sync the data, `tsc --noEmit`, `vite build` into `dist/`, then print bundle and data sizes |
| `npm run preview` | serve `dist/` at the base path on port 4173 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run test` | Vitest: the policy engine against the shared fixtures, validators, csv, ledger, receipts, sandbox |
| `npm run test:e2e` | sync the data, build, then Playwright (chromium) against `vite preview` |
| `npm run lint` | eslint (typescript-eslint + react-hooks) |
| `npm run size` | gzip sizes of the built bundle and of every data file |
| `npm run sync-data` | copy `artifacts/lab/**/{*.json,*.csv.gz}` and `fixtures/synthetic_sandbox.json` into `public/data/` |
| `npm run mock-data -- <dir>` | write a clearly labelled MOCK export for running without `artifacts/lab/` |

Node >= 22 (`.nvmrc`), npm with the committed `package-lock.json`. Chromium for e2e:
`npx playwright install chromium`.

## Data contract

The app is built against the seven schemas in `artifacts/schemas/`:

| file (served from `<base>/data/`) | schema |
|---|---|
| `manifest.json` | `lab_manifest.schema.json` |
| `snapshot.json` | `lab_snapshot.schema.json` |
| `cases.json` | `lab_cases.schema.json` |
| `replay/replay_<method>.json` + `replay/replay_<method>.test.csv.gz` | `lab_replay_meta.schema.json` (CSV columns `v1,v2,n_candidates,labelled,top1_correct,truth_reachable`; empty field = null) |
| `synthetic_sandbox.json` | `lab_synthetic_sandbox.schema.json` |
| exported receipts | `lab_receipt.schema.json` |
| exported / stored ledgers | `lab_review_events.schema.json` |

`src/lib/contracts.ts` holds hand-written strict validators for all of them (required keys, closed
objects, enums, id patterns); anything else is rendered as a "malformed data" error state.
`src/lib/policy.ts` mirrors `entity_resolution/decision_lab/policy.py`; `npm test` reproduces
every expected value in `fixtures/policy_fixtures.json` bit for bit (Python's `round(x, 6)`
including half-to-even ties is mirrored by `round6`).

The default screen fetches only `manifest.json` and `snapshot.json`. Cases, replay bundles and
the sandbox fixture are fetched by the views that need them. Replay bundles are inflated in the
browser with `DecompressionStream('gzip')`; when a browser lacks it, the replay view says so
and everything else keeps working. (Some dev servers send `.gz` files with
`Content-Encoding: gzip`, so the loader checks the gzip magic number before inflating.)

## Base path

`vite.config.ts` sets `base: '/entity-resolution/lab/'` (the GitHub Pages path next to the
results page at `../` and the dbt docs at `../dbt/`). Override it for a local preview with
`LAB_BASE=/ npm run build && npm run preview`. Routing is hash based (`#/compare`, `#/cases`,
`#/cases/<a_id>`, `#/replay`, `#/sandbox`, `#/receipt`, `#/provenance`) so direct loads work on
Pages; shareable scenario state lives in query params after the hash path (for example
`#/compare?method=rules_v1&floor=0.5&budget=20000`). Rationale text and review events are never
put in the URL.

## Local decisions

Review events are an append-only ledger in memory, persisted to `localStorage` under
`erlab:v1:<snapshot_id>:<analytical_digest>`. Corrupt or incompatible stored data is reported
and left untouched. Exports and imports (ledger and receipts) are validated against the
contracts and refused when the snapshot id or analytical digest differ. Sandbox decisions are
namespaced `synthetic:*` and never enter a real consequence count or a receipt.

## Mock-data mode

When `artifacts/lab/manifest.json` is missing, `sync-data` fails loudly and nothing is
fabricated. To run the app and its tests without the real export:

```
npm run mock-data -- /tmp/erlab-mock          # writes a MOCK export (every value invented)
LAB_DATA_DIR=/tmp/erlab-mock npm run dev      # or build / test:e2e
```

The mock is generated by `scripts/mock-lab-data.ts` from a seeded generator; its snapshot metrics
are computed from its own replay rows with the same policy engine, so the replay at the native
policy reconciles exactly, as it must for the real export. The mock is labelled as such in every
note field and must never be published.
